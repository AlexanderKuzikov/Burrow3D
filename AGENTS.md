# Burrow3D — Instructions for AI Agents

Приложение — три файла в корне (`index.html`, `biomes.js`, `maps.js`), без сборки и без
рантайм-зависимостей. Остальное — проверки, тесты и документация.
Правки вносятся прямо в эти три файлы.

## Commands

| Задача | Команда |
|--------|---------|
| Запуск | открыть `index.html` в браузере (double-click работает, но **пропсы не грузятся**: см. грабли №21) |
| Запуск по HTTP | `npm run serve` → `http://127.0.0.1:8801/` — единственный способ увидеть пропсы |
| Пропсы | `npm run props` — копия манифеста и GLB из `../NexusModeler/export/land` в `props/`. **Нужна перед чеком, тестами и сборкой** |
| Проверка данных | `npm run check` — карты, наборы, ссылки наборов на объекты и части, **пропсы**, **выгруженные скины** |
| Выгрузка кожи | `npm run export` — по файлу на набор **с пропсами** в `dist/skins/`. Нужна перед `npm run check` |
| Тесты | `npm test` — Playwright, 11 сценариев в реальном Chromium |
| Тесты с UI | `npm run test:ui` |
| Сборка | `npm run build` — один автономный HTML в `dist/`, пропсы внутри. **Необязательна**: приложение работает и без неё, из исходников (кроме пропсов — они по `file://` не читаются) |
| Линт | **отсутствует** — его нет и не нужно изобретать |

Проверять перед коммитом: `npm run props && npm run export && npm run check && npm test`.
`npm run check` читает скопированное из `props/` и выгруженное из `dist/skins/`, поэтому без
них он падает с явным сообщением — и правильно: правка без новой копии или новой выгрузки
означает устаревшие данные. Сам чек экспорт и копирование не запускает, он остаётся чистым
Node без зависимостей.
`node_modules/`, `dist/`, `props/` и `scripts/vendor/` в репозиторий не попадают
(см. `.gitignore`). Playwright поднимает свой статический сервер сам, порт 8801 должен
быть свободен.

`index.html` — единый модуль, синтаксис проверяется только загрузкой в браузере.
После правок всегда проверяй консоль: ошибки видны в DevTools, `window.BURROW` даёт доступ к
сцене из консоли, `window.BURROW.propsReport()` — к составу пропсов.

Приложение остаётся тремя файлами в корне. `scripts/build.js` — единственное место,
которое знает про `dist/`, и оно же генерирует артефакт, а не меняет исходники.
`scripts/props.js` — единственное место, которое знает про `../NexusModeler`, и оно
**только читает**: писать в соседний проект нельзя никогда.

## Conventions

- **Стиль** — как в существующем коде: 2 пробела, `const`/`let`, стрелки, без `var`.
- **Комментарии** — только там, где объясняют *почему*, а не *что*. Грабли three.js описаны в коде.
- **Порядок в `biomes.js`** — `name`, `note`, `sky`, `water`, `relief`, `ground`, `scatter`.
- **Новый набор оформления** — скопировать существующий блок в `BIOMES` и поменять значения.
  Движок подстраивается сам: нигде не нужно регистрировать объект заново. **Имя ключа обязано
  совпадать с именем набора пропсов в `NexusModeler`** — иначе набор не покажется, и `npm run check`
  это поймает
- **Новый пропс** — не наша работа: геометрию делает `NexusModeler`. Наше дело — чтобы его слот
  доехал до предпросмотра и до поля `tiles`. Свой `kind`, свой слот или свой файл здесь не заводятся
- **Плотность по слотам** в коже не выдумывается: одна занятая клетка = один пропс, слот
  равновероятно из сорока. Если игра будет ставить иначе, править надо договорённость, а не
  плотность здесь
- **Горы задаёт `ridgeAmp`** в `relief`: поднимаются только занятые клетки, поля остаются
  долинами. `ridgeAmp: 0` — равнина с холмами. Значение ненулевое требует `ridgeFreq` и
  `ridgeOct`, иначе `npm run check` падает.
- **Ровность дороги** — `roadFlatten`: доля сглаженной высоты вместо собственного шума.
  Умножать высоту на маску нельзя (грабли №10), поэтому другого способа «выровнять» дорогу
  здесь нет.
- **Новый объект** — добавить в `BUILDERS` в `index.html`. Части объединяй через
  `mergeAll([...])`, чтобы не плодить `InstancedMesh`. Части без `id` нельзя перекрасить из набора —
  дай каждой `id`.
- **Русский язык** в комментариях, UI и документации. Идентификаторы — английский.
- **Цвета** — только `setHex(0x..., THREE.SRGBColorSpace)`. Значение `0x...` без указания
  цветового пространства читается как linear и будет темнее в 2.2 раза (см. грабли в `DECISIONS.md`).

## Грабли, которые нельзя повторить

1. **`InstancedMesh.setColorAt` без `vertexColors: true` не работает** вообще: `color_fragment`
   применяет `vColor` только под `USE_COLOR`. А r169 **удалил** `Material.defaultAttributeValues`,
   поэтому без явного белого атрибута `color` на геометрии он читается как (0,0,0) — объекты
   становятся чёрными. Отсюда хелпер `whiteColors()`.
2. **`Color.setHSL` по умолчанию не конвертирует** в рабочее пространство (в отличие от `setHex`).
   `instanceColor` трактуется как linear — sRGB-lightness приходится задавать явно.
3. **Байты в DataTexture пишутся в sRGB.** Считаем цвет в linear, потом
   `convertLinearToSRGB()` и только потом `* 255`, иначе двойной encode и земля уходит в чёрный.
4. **`fbm` возвращает узкий диапазон** (усреднение октав сжимает значения к 0.5). Для гор нужен
   отдельный `fbmRidged` — иначе `1-|2n-1|` даёт почти константу и получается плато.
5. **Индекс клетки умножается на `CELL`**: `originX + (cx + rnd()) * CELL`. Забыли `* CELL` —
   вся растительность сжалась в один квадрант карты.
6. **Два разных начала координат, и их нельзя смешивать.** `originX/originZ` — левый край
   **карты** (от него считаются позиции объектов, маски рельефа, миникарта). `planeX/planeZ` —
   левый край **полотна**, то есть карты плюс поле вокруг (от него считаются UV текстуры).
   Пока они были одним числом, клетка `cx` отображалась содержимым клетки `cx - ring`: вся
   сцена уезжала на ширину поля по обеим осям. Ошибка держалась с самого начала и была
   незаметна, пока объекты стояли на клетках обоих типов. Ловится тестом
   «клетка → мир → клетка».
7. **Кадр, туман и тени считаются от размера карты (`M.frame`), а не от плоскости с полем
   (`M.span`).** Иначе набор с широким полем отодвинет камеру и карта уйдёт на второй план
   пятном вдали. Ширина поля (`ring`) сама по себе на кадр не влияет.
8. **Тип клетки определяет проходимость, а не наоборот.** Препятствие (`solid`) на свободной
   клетке превращает её в занятую, камень на дороге перекрывает проход. `npm run check` падает
   на таком; лечится переносом правила в `scatter.blocked`.
9. **Браузер маскирует правки `biomes.js` и `maps.js` по HTTP.** Отдельные `<script src>`
   кэшируются независимо от `index.html`, поэтому `?v=...` на странице не помогает: правка
   в наборе не применяется, а выглядит как «ничего не изменилось». Проверяя руками, снимай
   кэш (в Playwright — `context().route` с `cache-control: no-cache`), а не полагайся на
   перезагрузку. `npm test` от этого защищён: Playwright запускает сервер заново.
10. **Высоту нельзя сглаживать умножением на маску.** Прежние `h *= 1 - roadFlatten*road`
   и `blockedFlat` давали уторок на границе маски: чем выше рельеф, тем выше ступенька.
   Замер на карте 40×40: ступенька между клетками дороги 1.9 против 0.4 на свободных, то есть
   «ровная» дорога была вчетверо грубее местности. Сейчас дорога интерполируется к
   сглаженному полю `S.hAvg`, горы складываются с маской — обе операции непрерывны.
11. **Обрыв отсчитывается от границы карты, а не от края полотна.** По краю полотна короткая
   сторона карты почти не обрывалась, а у наборов с водой край уходил под воду (лес: -19.7
   при воде -11). Теперь `out` — расстояние наружу от карты в долях ширины поля, и `rimDrop`
   не действует вообще внутри карты. Ширина поля одна для всех наборов: читаемость края
   задаёт обрыв, а не ширина пустого поля.
12. **`fbmRidged` неотрицателен** — поэтому горы можно добавлять к рельефу как есть. Если
    ввести вычитание среднего (`n - mid`), занятые клетки начнут местами уходить ниже базовой
    отметки и тонуть вместе с краем карты.
13. **Браузер не умеет перечислять файлы в папке, а `fetch` на `file://` заблокирован.**
    Поэтому «взять все `.json`, которые лежат рядом» невозможно без жеста пользователя —
    только выбор папки (`<input webkitdirectory>`). Не обещай в UI и документации
    автопоиска каталога: это не наша недоработка, а ограничение платформы. По той же
    причине `<script src>` на `file://` работает, а чтение `.json` как данных — нет.
14. **three.js вкладывается как `data:`-URL в importmap**, и это проверено на `file://`.
    Склеивать модули вручную (срезать `export`, заменить `import` на деструктуризацию)
    вышло бы на 500 КБ меньше, но требует правки чужих исходников — не брать. Аддоны
    адресуются в importmap **точными** путями: префиксное сопоставление не годится,
    к `data:`-URL нельзя относительно достроить путь.
15. **Подпись с прозрачным `<input>` поверх (`class="filebtn"`) — это кнопка**, и она
    должна быть в селекторе `button,select,.filebtn`. Иначе она выглядит текстом: с одной
    такой подписью в панели это не бросается в глаза, с двумя строка ломается.
16. **`ruleDensity()` — это математическое ожидание цикла в `buildScatter`, и они обязаны
    меняться вместе.** Счётчики в скине считаются по `ruleDensity`, объекты на экране —
    по циклу. Если поменять только цикл, скин начнёт врать, а заметят это только глаза.
    Ловит тест «кожа выгружается детерминированно…»: он сравнивает сумму счётчиков с
    реальным числом объектов и требует расхождения меньше 15 %.
17. **Контракт скина не содержит перечислений — и это не метафора.** Ни списка наборов,
    ни списка объектов, ни «известных» имён в нём быть не должно: игра не знает наших имён
    и узнавать не должна. Всё, что нужно для рисования, лежит в самом правиле. Поэтому
    добавление набора или объекта не должно требовать правки формата — если требует,
    значит в контракт просочился список.
18. **`npm run check` проверяет выгруженное, а не исходники.** Правка набора без
    `npm run export` обязана валить чек: иначе устаревшая кожа уедет в игру молча.
19. **`CELL` и `scatter.cell` — разные величины, называть их похоже нельзя.** `CELL = 2`
    это мировых единиц в одной клетке карты; `SKIN_BLOCK` — сторона блока счётчика в
    клетках. Первое объявляется в контракте как `cellSize`, потому что без него игре
    неизвестен масштаб: ландшафт вышел бы вдвое мельче, а `blockedLift` — вдвое меньше.
    Величину `CELL` менять нельзя: на ней отстроен весь вид набора.
20. **В скине `fingerprint`, а не `hash`.** FNV-1a на 32 бита сверяет «этот скин к этой
    карте», но целостности не гарантирует — для этого есть `contentHash` на sha256. Называть
    его хэшем значит сеять ровно ту путаницу, ради которой переименование и затевалось.
21. **`file://` не читает файлы как данные, и это касается пропсов тоже.** `fetch` на `file://`
    заблокирован, поэтому из исходников по двойному клику лес не грузится: приложение
    показывает отказ с текстом про `npm run serve`, а не рисует вместо пропсов свои объекты.
    В `dist/burrow3d.html` пропсы вложены как `data:`-URL, поэтому артефакт работает целиком.
    Не «чини» это откатом на `BUILDERS` — это ровно то расхождение, которое закрываем
22. **Откат на процедурные объекты на занятых клетках запрещён по существу, а не по правилу.**
    Набор без пропсов не показывается и не выгружается: вместо сцены надпись с причиной.
    Одиннадцать из девятнадцати объектов `BUILDERS` на этих клетках больше не рисуются, и
    `npm test` требует, чтобы там не появилось ни одного `InstancedMesh` с `src: 'rule'`
23. **`GLTFLoader` тянет относительный импорт `../utils/BufferGeometryUtils.js`, и к
    `data:`-URL относительно не достроишь.** В собранном файле этот импорт перевешен на
    точный путь importmap; без правки артефакт падает на `file://` с «не найдено». Правку
    делает `scripts/build.js` и падает, если импорт не ровно один — three обновится, и тогда
    правь сборщик
24. **Модели `NexusModeler` считаны в единицах игры, где клетка равна единице.** У нас клетка —
    `CELL` мировых единиц, поэтому масштаб пропса ровно `CELL`. Масштабировать «под вид»
    нельзя: предпросмотр обязан совпадать с игрой
25. **Счётчик в коже отвечает на вопрос про правило, а не про всю картинку.** На занятых
    клетках рисуются пропсы, у которых в контракте нет ни `per`, ни `scale`, поэтому сумма
    счётчиков сверяется с числом **процедурных** объектов. Сверять её со всем, что на
    экране, нельзя — тест специально делит их и требует все сорок слотов отдельно
26. **Причина отказа — одна на предпросмотр и выгрузку** (`propsRefusal()`). Иначе надпись и
    сообщение об отказе рано или поздно скажут разное, и придётся гадать, какое из двух
    объяснений верно

## Do NOT touch

- Скриншоты в `docs/` — только `.jpg`, качество 84, размер 1280×720. Перегенерировать — когда
  меняется вид, и не иначе: репозиторий растёт на мегабайты. Снимаются скрытой панелью
  (`#left` в `display: none`), кроме `screenshot-ui`. Перед перегенерацией снять кэш
  (грабли №9), иначе снимутся старые кадры. **Шесть кадров наборов без пропсов устарели** —
  на них старый вид с процедурными объектами; обновятся, когда штаб закроет наборы
- `LICENSE` — Apache-2.0, текст не редактировать.
- Встроенную карту `burrow-01` в `maps.js` — это исходная карта пользователя, 1:1 из
  `burrow-01(2).json`. Не «выравнивать» и не переформатировать строки.

## Documentation rules

- После работы — обнови `docs/CONTEXT.md`: статус, открытые проблемы, журнал.
- Архитектурное решение — запись в `docs/DECISIONS.md` (append-only).
- Новый `.md` в `docs/` — только с разрешения пользователя.
- Переиспользуемые знания (грабли three.js, приёмы рендера) — в
  `D:\GitHub\knowledge\` с записью в `knowledge/README.md`.
- Коммиты — прямо в `main`, по-русски или по-английски, императив, ≤72 символа в заголовке.

## Работа в этом проекте

- **Коммитить и пушить самому, не спрашивая.** Пользователь снял требование подтверждения:
  после `npm run check && npm test` коммитим в `main` и пушим. Спрашивать нужно только
  `force-push`, `reset --hard` и всё, что необратимо.
- **Актуальность документации — часть работы, а не отдельная задача.** Правка кода без
  правки документации считается недоделанной. Сверять надо число за числом: версия в
  `package.json` и в README, число сценариев тестов и `test(`, имена ключей схемы в
  `biomes.js` и в шапке файла, ссылки на `test-results`/`playwright-report` в `.gitignore`
  и в структуре проекта. Устаревшее решение помечать явно («что здесь устарело»), а не
  молча переписывать — `DECISIONS.md` append-only.
- **Переводы строк в этом репозитории — только LF**, во всех файлах без исключения.
  Правка через PowerShell (`Set-Content`, `Get-Content -Raw`) и вывод `git show` в PowerShell
  искажают их, а измерение через PowerShell даёт неверный результат — проверять переводы
  node-скриптом, читающим байты.
