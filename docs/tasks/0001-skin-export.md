# 0001 — Выгрузка кожи: контракт, который переживает новые наборы и объекты

**Роль:** кодовая сессия `Burrow3D`.

**Это первая работа проекта, выданная по заказу штаба `Echoes-of-Burbenog`.** Не расширяй объём.

## Зачем

Третий слой карты — визуальный. Сейчас он существует только как окно браузера: посмотреть можно,
забрать нельзя. Игра должна получать вид **данными**.

**Решение владельца 2026-10-04: `Burrow3D` — инструмент, который рождает вид и отдаёт его данными.**
Второго источника геометрии не будет: **ландшафт — `Burrow3D`, башни и существа — `NexusDefense`.**

## Граница этой работы

**Содержимое — владельца.** Наборы, объекты, их количество и вид меняет владелец, и он же будет
менять их дальше. Эта работа делает **контракт выгрузки и саму выгрузку**, и ничего больше.

Отсюда главное требование, и оно важнее остальных вместе взятых:

> **Контракт обязан переживать новые наборы и новые объекты без изменения.**
> Владелец добавит набор или десять объектов — и ни формат, ни игра, ни чек не должны потребовать
> правки.

Практически это значит: **в контракте нет списков.** Ни перечисления наборов, ни перечисления
объектов, ни «известных» имён. Каждое правило несёт всё, что нужно для рисования, само.

## Что выгружаем

Один файл на **текущий набор оформления**, кнопкой рядом с выбором набора. Имя файла — из имени
набора. Формат зафиксирован:

```json
{
  "version": 1,
  "name": "desert",
  "map": { "width": 96, "height": 96, "hash": "<hex>" },
  "ground": { "free": ["#hex", "#hex"], "road": ["#hex", "#hex"], "blocked": ["#hex", "#hex"] },
  "relief": { "blockedLift": 0.6, "roadFlatten": 0.85, "roadSink": 1.05 },
  "light": { "sky": { }, "water": { } },
  "scatter": {
    "cell": 8,
    "rules": [
      {
        "id": "desert.tuft",
        "builder": "tuft",
        "cellType": "free",
        "solid": false,
        "layer": "plants",
        "scale": [0.55, 1.25],
        "jitter": 1,
        "tilt": 0.2,
        "colors": { "blade": ["#hex", "#hex"] },
        "glow": { },
        "geometry": null,
        "density": [0, 0.4, 1.2, 0, 0, 0.7, 0, 0, 0, 0, 0.3, 0, 0, 0, 0.9, 0, 0, 0]
      }
    ]
  }
}
```

**`density` — главное в этом файле.** Сетка «сколько объектов этого правила ожидается в блоке
`8 × 8` клеток»: та же формула, что разбрасывает объекты сейчас, посчитанная по клеткам нужного типа
внутри блока. Размер сетки — `ceil(width / 8) × ceil(height / 8)`.

**Почему плотности, а не шум.** Если отдать игре параметры шума, шум придётся реализовать в игре второй
реализацией, и она разойдётся с вашей на первой же правке. Плотности по блокам совпадают всегда и не
требуют от игры ничего, кроме разброса внутри блока.

**`builder` — поле только для чтения человеком.** Это ваше внутреннее имя, чтобы в файле было видно,
что за объект. **Игра не должна по нему ничего искать:** игра не знает имён ваших объектов и узнавать
не должна, иначе первый же новый объект потребует правки в игре. Всё, что нужно игре, лежит в самом
правиле.

**`name` — свободная строка, не перечисление.** Игра не переключается по нему.

**`geometry`** — ссылка на файл объекта, значение `null` в этой работе. **Поле нужно уже сейчас,
чтобы контракт не поехал, когда появится выгрузка геометрии.** Сама выгрузка GLB — отдельная работа
и отдельное решение.

**`map.hash`** — хэш файла карты: игра по нему узнает, что скин выгружен под эту карту, и не
применит к другой.

**Неизвестные поля игра обязана игнорировать, а не падать на них.** Поэтому в файл можно класть
что угодно ещё, и добавление набора не должно требовать поднятия `version`. `version` растёт только
если меняется **форма**, а не содержимое.

## Чего не делать

- **GLB в этой работе нет.** Поле `geometry` остаётся `null`.
- Не менять рельеф, наборы, объекты и рендер. Это выгрузка данных, а не рефакторинг.
- Не выдумывать новых наборов и объектов: это владельца.
- Не трогай `Echoes-of-Burbenog`. Читать можно, писать нельзя.
- Не менять `LICENSE`, встроенную карту `burrow-01` в `maps.js` и скриншоты в `docs/`.
- Не создавай `.md` без разрешения владельца.

## Что должно сойтись

1. **Выгрузка детерминирована.** Две выгрузки подряд дают побайтово одинаковый файл. В содержимое не
   попадают время, случайные числа и порядок обхода, зависящий от вставки в объект.
2. **`npm run check` проверяет выгруженное**, а не только ваши данные: у каждого правила есть
   `builder` в `BUILDERS`, `solid` совпадает с ним, `solid: true` не встречается у свободной клетки и
   дороги, плотности в `0..`, размер сетки плотностей равен `ceil(w/8) × ceil(h/8)`, `map.hash`
   совпадает с картой. Чек обязан проходить для **всех** наборов, а не для одного.
3. **Round-trip:** выгруженный файл читается обратно и проходит те же проверки. Плюс тест на то, что
   повторная выгрузка даёт тот же файл, на карте 96 × 96 — худший случай по размеру сетки.
4. **Ничего не сломалось:** `npm test` — те же 10 сценариев зелёные, `npm run build` собирается.
5. **Плотности осмысленны:** сумма плотностей по карте 96 × 96 даёт число объектов того же порядка,
   что сейчас ставится на экране. Назови оба числа.
