# 0003 — Кожа таскает пропсы вместо своих процедурных объектов

**Роль:** кодовая сессия `Burrow3D`.

**Указание штаба, не обсуждается.** Решение о связи проектов принято штабом и передано тебе как
готовое: **имена наборов принадлежат `NexusModeler`** (`D:\GitHub\NexusModeler\export\land\manifest.json`,
записи `land.<сет>.<NN>`), список на 2026-10-05 — `forest`, `desert`, `mountains`, `mars`, `venus`,
`glacier`, `fungal`. Ключ набора в `biomes.js` обязан совпадать с именем набора пропсов, и **сегодня это
тождественное отображение, а не совпадение.**

## Зачем

Сейчас `Burrow3D` рисует свои 19 процедурных объектов, а игра получит геометрию из `NexusModeler`.
**Одна и та же карта в предпросмотре и в игре выглядит по-разному**, и это то самое расхождение,
ради которого редактор карты и выгрузка моделей вынесены в отдельные проекты. Расхождение возникло
предсказуемо: каждый проект делал свою часть и считал, что она и есть результат.

## Что сделать

**1. Кожа выгружает слоты.** В файл кожи добавляется блок `tiles` — все сорок слотов выбранного набора:
`slot`, `kind`, `footprint`, `solid` и ссылка на файл модели. **Поле аддитивное**, `version` остаётся 1.

**2. Предпросмотр грузит модели, а не рисует свои.** Объекты из `BUILDERS` для деревьев, камней и
прочего на **занятых клетках** заменяются на `GLB` из манифеста пропсов. Загрузка — обычным
`GLTFLoader`, по правилам контракта: без расширений, своих нод и нестандартных атрибутов.

**3. Набор без пропсов не выгружается и не показывается.** Это главное правило задачи. Пропсы
приняты только для `forest`, остальные шесть наборов ещё без геометрии.

- **Никакого запасного пути на процедурные объекты.** Откат на них и есть то расхождение, которое мы
  закрываем.
- Попытка выгрузить скин набора без пропсов **отказывает с внятной причиной по имени набора и по
  числу недостающих слотов**, а не выгружает неполный файл.
- Предпросмотр такого набора показывает **надпись с этой причиной**, а не сцену с другими объектами.

**4. Проверка целостности.** `npm run check` падает, если: слот вне `1…40`, `kind` не из списка,
`footprint` не 1 и не 2, `solid: true` у `bush` и `bone`, не хватает слотов, имя набора в `biomes.js`
не совпадает с набором пропсов, у записи пропса нет файла на диске или его `contentHash` разошёлся с
манифестом.

## Чего не делать

- **Свои процедурные объекты не удаляй.** Они остаются в `BUILDERS` для других наборов и как запас на
  случай, если владелец решит иначе. Задача — перестать их рисовать там, где есть пропсы.
- Не трогай `maps.js`, рельеф, палитры, свет и плотности: это твоя часть, она не переигрывается.
- Не трогай соседние проекты, в том числе `NexusModeler`. **Читать его манифест можно, писать нельзя.**
- Не создавай `.md` без разрешения владельца.

## Чем мерится сдача

   Назови текст отказа.
5. **Детерминированность держится:** две выгрузки подряд побайтово равны, включая `tiles`.

## Отчёт сессии 0003

### 1. Что сделано

**1. Кожа выгружает сорок слотов.** В файле появился блок `tiles` — все сорок слотов
выбранного набора по порядку номера. Поле аддитивное, `version` осталась 1:

```json
"tiles": [{ "slot": 1, "kind": "tree", "footprint": 1, "solid": true,
            "file": "land-forest-01.glb",
            "contentHash": "sha256:2a769bacd36abb91c65aa32ffe6c792a97b62d0c39ef92940e2d1aa99e171433" }]
```

`file` — имя, а не путь: игра ищет свою копию по имени, путь у неё свой. `contentHash`
рядом не для красоты: это сверка целостности, ровно та величина, которой
`map.fingerprint` не является (грабли №20).

**2. Предпросмотр грузит модели.** На занятых клетках теперь GLB из манифеста, обычным
`GLTFLoader` — без расширений, своих нод и нестандартных атрибутов, ровно как требует
контракт `NexusModeler`. По одному `InstancedMesh` на слот, все сорок. Правила
`scatter.blocked` в `biomes.js` не тронуты, но на занятых клетках больше не рисуются:
в `BUILDERS` нет ни одного `InstancedMesh` с `src: 'rule'` и `cellType: 'blocked'`, и
тест это требует. Процедурные объекты остались в `BUILDERS` — для свободных клеток и
дороги, и как запас, как велено.

**3. Набора без пропсов нет ни в выгрузке, ни в предпросмотре.** Ни отката на
процедурные объекты, ни частичного файла. Одна функция `propsRefusal()` даёт текст и
надписи в сцене, и отказу выгрузки — расходиться они не могут.

**4. Проверка целостности.** `npm run check` получил раздел про пропсы и сверку `tiles`
с манифестом. Реестр слотов (`TILE_SLOTS`, `TILE_KINDS`, `TILE_SOLID`) вытаскивается из
`index.html` текстом, ровно как уже вытаскиваются `CELL` и `mapFingerprint`, — поэтому
чек и движок разойтись не могут.

Попутно, по необходимости:

| Что | Зачем |
|-----|-------|
| `npm run props` (`scripts/props.js`) | копия манифеста побайтово и 40 GLB из `../NexusModeler/export/land` после сверки каждого файла по sha256. `props/` в `.gitignore` |
| `npm run export` переписан на частичный успех | наборы без пропсов печатают причину и пропускаются; каталог `dist/skins/` переписывается целиком, иначе там остался бы скин без `tiles` |

### 3. Что не сходилось, пока чинил

1. **`GLTFLoader` внутри `data:`-URL не грузился вообще.** У аддона есть относительный импорт
   `../utils/BufferGeometryUtils.js`, а к `data:`-URL относительно не достроишь. Собранный
   файл падал по `__MAP_READY` и тихо показывал пустую сцену — выглядит как «не грузится
   three», хотя три.js на месте. Сборщик перевешивает этот один импорт на точный путь
   importmap и падает, если импорт не ровно один: three обновится, и тогда правь сборщик
2. **`loadAsync` возвращает GLTF, а не сцену.** Первый вариант делал `t.scene = gltf`, и
   `buildProps` падал на `scene.traverse is not a function`. Поле называется `gltf`,
   сцена — `gltf.scene`
3. **Номер в имени двузначный, а в `land.slot` — число.** Сверка строк дала 39 ложных
   «в имени номер 01, а в land.slot 1». Теперь сверка числовая, и комментарий рядом
   объясняет, почему строкой здесь нельзя
4. **Сообщение про `solid: true` у `bush` заканчивалось пустотой** — оно печатало «проходимы
   только » и список оставляло пустым, потому что фильтр был написан наоборот. Теперь
   называются именно проходимые виды
5. **Счётчик в коде выводился как `total - procTotal` — величина, которой нет ни в одном
   тесте и ни в UI в явном виде.** Разделил: `count` (всего), `props`, `procedural`. Тест
   сверяет счётчики именно с `procedural` — иначе они разошлись бы на 1659 инстансов
6. **Собранный файл с пропсами дороже на 1,6 МБ.** Это цена офлайна, и я её заплатил
   сознательно: артефакт отдают заказчику, он открывается двойным кликом, и лес в нём
   должен быть. Обратный вариант (не вкладывать, показывать отказ) означал бы, что
   ровно тот файл, который отдают, не показывает главное — отмечено в открытых проблемах
7. **Шесть скриншотов галереи стали ложью.** На них наборы без пропсов с процедурными
   объектами, которых в приложении больше нет. Не стал генерировать шесть одинаковых
   карточек отказа (репозиторий растёт на мегабайты, а толку ноль) — пометил устаревшими
   в README, AGENTS и CONTEXT и обновлю, когда штаб закроет наборы

### 4. Три места, где пришлось решить самому

**Плотности по слотам в коже.** В `tiles` не добавлено ни `per`, ни `scale`, ни `jitter`.
Одна занятая клетка получает один пропс, слот равновероятно из сорока, первые сорок клеток
получают по одному каждому слоту. Обоснование: плотностей по слотам нет ни в контракте
`NexusModeler`, ни в коже, и выдумать их здесь — значит вернуть то расхождение между
редактором и игрой, которое задача и закрывает. Если игра будет ставить иначе, править
надо договорённость, а не плотность здесь. Записано в открытые проблемы.

**Пропсы не в репозитории.** `props/` под `.gitignore`, копия скриптом из
`../NexusModeler`. Цена — в чистой копии репозитория без соседнего проекта лес покажет
отказ с текстом «выполни `npm run props`». Альтернатива — 1,08 МБ чужих бинарников в git
и риск разъехаться на версии. Путь переопределяется `PROPS_SRC`.

**Шесть наборов не рисуются вовсе.** Формально можно было оставить им процедурные объекты с
пометкой в интерфейсе — инструмент стал бы «полнее». Отверг: предпросмотр продолжал бы
показывать не то, что увидит игрок, а это и есть причина, по которой проекты разнесены.

### 5. Чего не делал

`maps.js`, рельеф, палитры, свет, плотности и правила `scatter.blocked` не трогал — это моя
часть, она не переигрывается. `BUILDERS` не чистил: одиннадцать объектов на занятых клетках
не рисуются, но они нужны свободным клеткам и остаются запасом. Соседние проекты не писал:
`NexusModeler` только читал, путь к нему зашит в одном месте (`scripts/props.js`) и
переопределяется переменной. Новых `.md` не создавал — отчёт здесь.
