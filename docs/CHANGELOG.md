# Burrow3D — CHANGELOG

## 0.6.0 — 2026-10-05

### Исправлено

- **`cellSize` в контракте кожи** — вещь, которая ломала игру. В инструменте клетка карты
  это две мировые единицы, в игре одна клетка это одна единица, и в контракте это не было
  объявлено: игра взяла бы скин и нарисовала ландшафт вдвое мельче, а `blockedLift: 2.5`
  превратился бы в 1.25. Величина `CELL = 2` не менялась — решение владельца, на нём
  отстроен весь вид; единицы объявлены в контракте, перевод делает игра
- **`map.hash` → `map.fingerprint`.** Это FNV-1a на 32 бита: сверка «этот скин к этой карте»,
  но не целостность. Рядом в нашем же стеке лежит `contentHash` на sha256, который легко
  принять за него; теперь путаницы нет ни в формате, ни в сообщениях чека

### Изменено

- `density` переименована в `count` — в поле лежал счётчик, а не плотность
- `scatter.cell` 8 → 4: сетка счётчиков на карте 96×96 стала 24×24 вместо 12×12,
  пейзаж перестал быть однообразным на больших площадях
- В правило добавлена высота парения части `float` — без неё игра не повторила бы парящие
  споры. Аддитивное поле, версию не поднимает
- **`version` осталась 1**, полный состав перечислен списком в шапке блока выгрузки кожи
  в `index.html` — чтобы потом не спорить, что было в первой версии
- Размер скинов 9–17 КБ → 28–50 КБ
- `npm run check` сверяет `cellSize` с `CELL` из движка, а не «просто число»; появились
  проверки `float` и `cellSize` на отсутствие
- Версия 0.5.0 → 0.6.0

## 0.5.0 — 2026-10-04

### Добавлено

- **Выгрузка кожи.** Кнопка «Выгрузить кожу» в верхней панели отдаёт набор оформления и
  текущую карту одним JSON: цвета земли, три числа рельефа, свет и правила расстановки.
  Вместо параметров шума в файле — плотности по блокам 8×8 клеток, то есть математическое
  ожидание той же формулы, по которой объекты раскладываются на экране. Игра не повторяет
  шум и потому не разойдётся с нами на первой правке набора
- **Контракт без перечислений:** ни наборов, ни объектов, ни «известных» имён. `builder`
  в правиле — имя для чтения человеком, по нему игра ничего не ищет. Добавление набора
  или объекта ничего в формате не ломает
- `npm run export` — выгрузка кожи всех наборов в `dist/skins/`. Идёт через браузер и зовёт
  ту же функцию, что и кнопка, поэтому разойтись они не могут
- `npm run check` теперь проверяет **выгруженное**: `builder` есть в `BUILDERS`, `solid`
  совпадает с ним и не встречается у свободной клетки и дороги, плотности в `0..`, длина
  сетки равна `ceil(w/8) × ceil(h/8)`, `map.hash` совпадает с картой, состав правил совпадает
  с `biomes.js`. Требуется скин каждого набора; устаревшая кожа валит чек
- Поле `geometry: null` уже в контракте — выгрузка геометрии отдельная работа, но форма
  не должна поехать, когда она появится
- Тест «кожа выгружается детерминированно, читается обратно и совпадает с картинкой»:
  две выгрузки подряд побайтово равны, файл читается назад, кнопка отдаёт файл с именем
  из имени набора, а сумма плотностей свереяется с реальным числом объектов

### Изменено

- Тестов 10 → 11. Версия 0.4.0 → 0.5.0
- Порядок перед коммитом: `npm run export && npm run check && npm test`. Чек читает
  выгруженное, поэтому без экспорта он падает — и правильно
- Имя файла карты при сохранении чистится общим хелпером `safeName` — раньше тот же
  regex был написан дважды, в кнопке карты и в выгрузке кожи

### Известная неточность

- `docs/screenshot-ui.jpg` показывает верхнюю панель без кнопки «Выгрузить кожу»:
  работа велась по заказу, где запрещено трогать скриншоты в `docs/`. Расхождение
  временное, перегенерировать снимок — отдельное решение владельца

## 0.4.0 — 2026-10-04

### Добавлено

- **Сборка в один автономный HTML.** `npm run build` → `dist/burrow3d.html` (1.83 МБ):
  движок, наборы оформления и демо-карты внутри, three.js лежит как `data:`-URL в importmap.
  Файл открывается двойным кликом и не ходит в сеть — проверено на `file://` с перехватом
  запросов. `dist/` и `scripts/vendor/` в репозиторий не попадают
- **Карты из своей папки.** Кнопка «Из папки» берёт все `.json` из выбранной папки — обычно
  той же, где лежит страница — и добавляет их в список карт. Имена берутся из имён файлов,
  некарты не ломают страницу, а встроенный список карт остаётся нетронутым
- Тест «карты из своей папки попадают в список» и тест «собранный файл самодостаточен:
  ни одного запроса наружу». Второй пропускает себя, если `dist/` нет

### Исправлено

- Подпись выбора файла (`class="filebtn"`) не имела стиля кнопки: правило `button,select`
  её не покрывало, и в панели она читалась как обычный текст. Всплыло при добавлении
  второй подписи — вторая переносила строку, и панель выглядела сломанной
- Поле шириной 1280×720, а не 1600×1000, как было написано в `AGENTS.md` — приводим
  документ в соответствие с файлами, чтобы не раздувать репозиторий

### Изменено

- Тестов 8 → 10. Версия 0.3.0 → 0.4.0

## 0.3.0 — 2026-10-04

### Исправлено

- **Край карты уходил под воду или не читался.** Обрыв считался от края полотна, а не от границы
  карты, и потому съедал край: у леса медиана высоты по краю карты была -19.7 при воде -11, то
  есть карта тонула целиком; ледник и горы — тоже. Обрыв теперь отсчитывается от границы карты
  и не действует внутри её. Обе границы заданы в долях ширины поля, поэтому край выглядит
  одинаково на картах любого размера, и ширина поля стала одна для всех наборов вместо
  «узкая у воды, широкая без воды»
- **Дорога была грубее ровного места.** Сглаживание умножением высоты на маску давало уторок
  ровно на границе маски: на карте 40×40 ступенька между клетками дороги была 1.9 против 0.4
  на свободных. Дорога теперь интерполируется к сглаженной высоте — и стала самым ровным
  участком на карте
- **Набор «Горы» был бугристым по всей карте.** Ridged-мультифрактал применялся ко всей
  поверхности; свободные клетки поднимались до +21 вместе с занятыми. Горы поднимаются только
  на занятых клетках, поля между ними остались долинами
- Ледник: вода опущена с -8 до -11 — при прежней амплитуде половина края карты оказывалась
  ровно на уровне воды

### Добавлено

- Тест «край карты, дорога и горы ведут себя как задумано»: три демо-карты × семь наборов,
  проверяет край выше воды, ровность дороги и то, что горы достаются только занятым клеткам
- Сетка сглаженной высоты (`S.hAvg`) — «по чему едет дорога»
- `water.flood` в наборе: честно помечает карту, которая затапливается намеренно (болота Венеры)

### Изменено

- Схема `relief`: `ridged`/`ridgedMid`/`blockedFlat` заменены на `ridgeAmp`/`ridgeFreq`/
  `ridgeOct`, `rimStart` и новый `rimEnd` задаются в долях ширины поля
- Сборка сцены на карте 96×96: 41–104 мс → 100–310 мс

## 0.2.3 — 2026-10-04

### Исправлено

- **Сцена была сдвинута относительно карты на ширину поля по обеим осям.** Начало координат
  карты и полотна хранилось одним числом, поэтому клетка `cx` отображалась содержимым клетки
  `cx − ring`. Лесные массивы стояли рядом со своими тёмными участками, а сами участки
  оставались пустыми. Разведены `originX/originZ` (край карты) и `planeX/planeZ` (край полотна)
- Лесной пол: подлесок вместо травы (светлая крошка на тёмном полу читалась как мусор),
  плотность деревьев повышена, палитра приведена к цвету лиственной подстилки

### Добавлено

- Тест `клетка → мир → клетка` и сверка текстуры с типами клеток: рассогласование слоёв
  больше не пройдёт молча

## 0.2.2 — 2026-10-04

### Добавлено

- `npm run check` теперь падает, если непроходимый объект поставлен на свободную клетку

## 0.2.1 — 2026-10-04

### Добавлено

- **`npm run check`** — проверка целостности данных без зависимостей: у демо-карт ровные строки,
  у наборов заполнены обязательные поля, каждый упомянутый объект существует в движке,
  каждый ключ в `colors`/`glow` совпадает с `id` части, границы тумана растут
- **`npm test`** — 6 сценариев Playwright в реальном Chromium: сцена построилась, все наборы
  переключаются, карты разбираются на три типа, легенда меняет разбивку, слои и камера не ломают страницу
- `package.json` и `.gitignore`; Playwright поднимает статический сервер сам

### Исправлено

- **Край карты читался как плита.** Кромка считалась по максимуму координат, то есть была
  квадратной, и у наборов без воды (пустыня, Марс, грибная чаща) был виден прямой угол плоскости.
  Теперь кромка круглая, а у наборов без воды поле вокруг карты вдвое шире и обод отодвинут
- **Кадр, туман и тени считались от размера плоскости**, а не от размера карты: набор с широким
  полем отодвигал камеру, и карта превращалась в пятно вдали
- Имя файла при сохранении очищается от символов пути, пробелов и ограничителей

## 0.2.0 — 2026-10-03

Система: произвольные карты и наборы оформления.

### Добавлено

- **Загрузка карт** — JSON через кнопку и drag-and-drop, размер и форма произвольны (проверено
  96×96, 56×28, 40×40, максимум 512)
- **Легенда символов** — три слота в панели с автоугадыванием и обменом местами при конфликте
- **Сохранение карты** — выгрузка JSON с приведённой легендой
- **7 наборов оформления** — Лес-Поле, Пустыня, Горы, Марсианская пустыня, Болота Венеры,
  Ледник, Грибная чаща; переключение без перезагрузки
- **19 объектов** — хвойные, лиственные, сосны, кактусы, сухой кустарник, камыш, грибы,
  гигантские грибы, кристаллы, ледяные шпили, снежные накаты, базальт, галька, валуны,
  кусты, лилии, споры, вентиляционные трубки
- **Слои** — Растительность / Камни / Декор / Тени
- **Ridged-мультифрактал** для гор
- **Миникарта** с сохранением пропорций карты
- Встроенные карты: `burrow-01` (96×96), `arena-56x28`, `isle-40x40`

### Изменено

- Рельеф, небо, туман, вода и свет описываются в наборе оформления, а не в движке
- Туман задаётся долей от размера карты (`fogK`), а не абсолютными единицами
- Расстановка объектов вынесена в общий конвейер с правилами (`scatter`)
- Камера по умолчанию кадрирует карту пропорционально её размеру

### Исправлено

- **Карта рисовалась зеркально по оси Z**: текстура соответствовала строке 95 там, где объекты
  стояли по строке 0. Затронуто 100% клеток. Миникарта при этом была верной
- **Газон сжимался в один квадрант карты**: в формуле размещения не учитывался размер клетки
- **Цвет земли уходил в чёрный**: значение цвета считалось в linear и записывалось в байты sRGB
- **Деревья и камни теряли цвет**: `instanceColor` не применялся без `vertexColors: true`,
  а в three r169 удалён `Material.defaultAttributeValues`
- **Цвета объектов были в 2.2 раза светлее задуманного**: `Color.setHSL` не конвертирует
  в рабочее пространство
